# Corpora

Versioned corpora of obligations, failures, and expected verdicts.

## `boogie/` — M1 corpus (≥500 obligations)

- `*.bpl` — hand-curated Boogie programs (arithmetic identities, min/max/abs/clamp,
  loop-invariant sum/count, array bounds via `select`, map `store`/`select`,
  quantified ranges, mod/div reasoning, one intentional vacuity case, one timeout case).
- `generated/*.bpl` — deterministic parameterized instantiations of the same families
  (`tools/gen_corpus.py`, fixed seed). Regeneration is idempotent; generated files are
  committed.
- `expected.json` — `obligation_identity -> {file, family, expected, proc}` for every
  corpus obligation. Designed families match their by-construction verdicts; observed
  families (nonlinear unknowns, the timeout case) record exactly what the pinned z3
  (5.1.0) returned at generation time. Timeout-family entries never discharge.

Corpus discipline: one assert per procedure (the obligation-identity tuple is
per-procedure). Verdicts re-run with z3 under the corpus budgets (≤2s per obligation;
timeout cases isolated behind the pytest `slow` marker, run with `pytest -m slow`).

Verify without solving: `uvil corpus verify corpora/boogie`.

## `failures/` — M2 cross-tool failure corpus (≥200 required-backend entries)

Standardized failures for repair-consumer experiments (M2 exit criterion: one
repair agent handles failures from ≥2 backends through the same interface).

- `smt/*.bpl` — z3-failure programs (`refuted-linear`, `refuted-bound`,
  `unknown-nonlinear`, `timeout-fermat`). Refutation families are designed
  (the negation is satisfiable by construction); unknown/timeout families are
  observed with the pinned z3 and never discharge.
- `parse/*.bpl` — out-of-M1-subset programs (`parse-if`, `parse-call`,
  `parse-uninterp`, `parse-type`, `parse-stray`); each import yields an I7
  `parse` diagnostic preserving the verbatim source line.
- `expected.json` — `entry (posix relative path) -> {file, backend, family,
  expected}` where `expected` is the I4 status (smt entries) or the I7 kind
  (`parse` entries). Generated by `tools/gen_failures.py` (fixed seed,
  idempotent, committed output).

Required backends are z3 + boogie-parser (both always available in-repo); the
cvc5 arm re-checks the `smt/*` entries through `Cvc5Backend` when `UVIL_CVC5`
is set (tests skip if absent). Timeout-family entries are isolated behind the
pytest `slow` marker (`pytest -m slow`).

## `c/` — M4 C harness corpus (50 ESBMC harnesses)

C verification harnesses checked by the pinned ESBMC binary (v8.5.0, release
tag `v8.5`; the adapter probes `UVIL_ESBMC`, PATH, then the documented
install dir — ADR 0004). Generated by `tools/gen_c_corpus.py` (deterministic,
idempotent, committed).

- `safe-assert` (15) — guarded identities; ESBMC verifies; import yields
  in-subset obligations.
- `overflow` (10) — assertions violated through C 32-bit wraparound or
  arithmetic; ESBMC violates; import yields obligations (the sequents stay in
  the unbounded-integer abstraction — which is exactly why a model-checking
  verdict must never upgrade them).
- `div-zero` (5) — unguarded division by a nondeterministic divisor;
  ESBMC's internal division-by-zero check fires; import yields obligations.
- `bounds` (10) — unguarded array indexing; ESBMC's internal array-bounds
  check fires; arrays are OUT of the sequent language, so import yields an
  I7 `parse` diagnostic (fail loud).
- `pointer-heap` (5) — malloc/deref patterns verified/violated through
  ESBMC's own pointer semantics; no Boogie lowering exists (the
  cross-language case); import is out-of-subset.
- `deep` (5) — deep nonlinear recurrence chains whose bit-blasted query
  exceeds any subprocess budget (expected: timeout); behind the pytest
  `slow` marker; import is out-of-subset.

`expected.json` — `stem -> {file, family, expected, import}` where `expected`
is the pinned binary's model-checking verdict at generation time (a run
record, never a deductive upgrade) and `import` declares what
`uvil.adapters.esbmc.import_c` must do. Live re-verification:
`uvil check-esbmc corpora/c/safe_*.c` (or the test suite with ESBMC on PATH).
